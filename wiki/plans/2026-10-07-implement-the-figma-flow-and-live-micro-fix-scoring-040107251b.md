## Context lifecycle and approved exclusions

**Missing** means there is neither a usable session graph nor persisted context for this file. The first Run audit is disabled until Generate context succeeds. **Cached** means persisted fragments exist but no verified session graph exists; display “Cached, will validate on audit.” A saved KnowledgeSummary alone does not establish either condition.

**Current** means this session has a complete graph for the confirmed profile/exclusions, with matching topology, a clean revision, verified resources and a wholeContextValidatedAt within the 15-minute validation window defined below. **Outdated** means its validation is old or edits/settings have invalidated it; show the reason and regeneration action. Age alone recommends regeneration but does not force capture when an explicit audit can revalidate unchanged context. Cached validation can still require a page walk and exports; show its actual progress.

**Generating** is a transient operation over the prior result. Failure or cancellation preserves the previous saved report and accepted cache, and shows the failure alongside the last successful summary. Recompute usable context status from the evidence actually retained: if a full build released the previous graph, do not continue claiming Current. Incomplete capture never becomes an accepted context.

Add a typed generate-context command and context-status events with progress and explicit completed, failed and cancelled outcomes. Reuse ScanProgress for an accessible progress bar, using determinate counts when available and an indeterminate state otherwise. Drive this command through ensureKnowledge without rule analysis or scan-result publication. Use existing command serialization and cancellation. Context generation must not retarget or replace the displayed saved report.

Generate/regenerate stages replacement context through the existing cache machinery. Explicit regeneration bypasses cache reads but can stage newly validated fragments for later reuse. Publish replacement cache data only after graph acceptance; optional cache-write failure does not invalidate a successful session graph or erase saved reports. Report generation and context generation remain distinct actions.

Persist the confirmed exclusion list as sorted, unique excludedPageIds in ReadinessProfile v3, under the new profile-v3 shared-plugin-data key. Read older profile keys and normalize v1/v2 profiles to v3 with no exclusions for live use. Preserve historical profiles verbatim in saved packets. Validate exclusions against actual pages, reconcile removed IDs visibly and keep role mappings separate from exclusion choices. Profile hashing then includes exclusions in graphProfileHash and fragment fingerprints.

Suggest only covers, separator pages and explicitly archive-marked pages using fixed page-name heuristics. Suggestions are unchecked until confirmed. Show the confirmed page names and an edit action. Changing exclusions invalidates current context and report authority; it never silently rewrites a saved result or auto-includes a dependency.

Keep the existing whole-file documentchange watcher and loadAllPagesAsync prerequisite. Skips reduce capture, inference and analysis; they do not promise to eliminate Figma page-loading cost. Preserve all page identities/names/order for topology checks, including excluded pages. Keep conservative invalidation for unknown or structural edits, including edits on excluded pages.

Add excludedPageIds to the internal graph and KnowledgeSummary. Retain internal graph schema 1 and context-fragment schema 2 with additive fields/defaults; missing exclusions mean none. Retain topology-only page records for excluded pages, with no captured node payload. loadedPageCount counts successfully captured included pages. Completeness means every non-excluded page was captured successfully, with no cancellation; it does not equate physically loaded watcher pages with captured evidence. Use this definition consistently in report readiness, pipeline.file-knowledge, freshness checks and summaries. A complete scoped capture passes the file-knowledge rule with evidence such as “N pages excluded by the designer”; an incomplete included page still fails.

Before auditing, reject a directly requested excluded page or selection and identify the required reinclusion. Check actual source dependencies of target roots, including nested instances' mainComponentId references, against the source's containing page. If required local source evidence is excluded or cannot be established, identify the page when known and require reinclusion/regeneration; never silently capture it or downgrade the missing dependency into a pass. Apply this guard to other explicit source references used by the target. Current responsive families and sibling-name uniqueness are page-local, so a whole-page exclusion cannot split an included family. Discovery-only repeated-structure analysis operates over the declared included scope. Continue resolving variables/styles independently of page exclusions.

Disable excluded pages in the page-batch picker and reject them in host requests. Preserve captured-target semantics, one verified graph per batch and existing cancellation/save-failure behavior.

Emit ReadinessReport v4 with target.excludedPageIds and verification provenance. Retain v1–v3 readers; absence of exclusions on historical reports means no recorded exclusions. Extend generated validators and relationship checks so v4 retains producer, coverage, category and issue-group invariants. Update profile normalizers/defaults, summaries, exports and fixtures together. Keep SavedAuditV1's outer schema 1 with validated optional additions and historical profile support.

## Bounded micro-checks and freshness

Check again is explicit after canvas edits. Route issue and module requests to a bounded path in recheck.ts/main.ts, separate from runScan, ensureKnowledge and refreshTrackedFragments. The existing module refresh becomes Check again using the same eligibility rules. A full Regenerate audit action retains the captured audit target and may explicitly rebuild context when necessary.

Extend requests with the displayed report hash and a request identity. Resolve the submitted issue/group/module against the host's displayed report and graph; never accept arbitrary node IDs or replacement evidence from the UI. Historical reports, mismatched report/graph hashes, changed profiles/exclusions and changed target topology cannot authorize a micro-check.

Initially support token bindings and applied text styles, layer naming, gap/padding changes on existing Auto Layout, annotations and export-name changes. Use a small explicit mapping from these fix kinds to live fields and dependencies. Mode changes, structural conversions, node insertion/deletion/reparenting, edited variable/style definitions and unknown properties require regeneration unless already covered by an explicitly supported case. Preserve the guarded structural repair behavior.

Add a field-scoped live reader in FigmaAdapter by extracting/reusing the relevant tokenPropertySnapshot, snapshotBase, text-style, inference and enrichLiveEvidence helpers. Patch only verified fields on staged copies; do not replace a complete NodeSnapshot with tokenPropertySnapshot's placeholder metadata. Retain unchanged identity, ownership, evidence and graph links. There is no buildKnowledge call, REST page export or whole-fragment recapture on this path.

The checked closure starts with the selected occurrences and verified source, plus every already-journaled supported change on captured nodes at the request's document revision. Include supported edits elsewhere in the audited target and on other included pages, with LOCAL and REMOTE edits treated alike. Thus fixing two supported issues before checking either re-reads both in one check; a supported remote edit on another included page is reconciled rather than causing regeneration solely because of its location.

For this combined set, include captured consumers of a changed component source, affected rendered text/background evidence and the geometry dependents of supported layout changes. Re-read affected values, bounds, inference and source/override evidence even when a dependent node has no direct change event. Derive dependencies from existing graph relationships and live identity checks. Read only the supported changed fields and their proven dependents. If the complete closure or required field evidence cannot be established within captured nodes, return requires-regeneration instead of widening into a full capture.

Retain changed-property sets per node in KnowledgeSessionState, with an unknown-change marker. On known nodes, boundVariables and textStyleId become eligible journaled changes rather than unconditional full-build reasons. Do not discard visual events merely because they concern a plugin-mutated node. Known plugin metadata changes must also be explicitly journaled when they affect findings.

A check proceeds only when every dirty node/property is accounted for by the combined supported closure, topology and profile match, and the resource environment is verifiable. Missing nodes, unsupported properties, structural changes or any remaining full-build reason require **Regenerate audit to verify**, with the displayed score unchanged, even when they occur outside the target. Do not infer independence solely from a node's location: report evaluation also uses graph-wide derived evidence. Preserve the conservative fallback for changes on excluded pages whose scene evidence was never captured. This path never throws into ensureKnowledge's FullKnowledgeRebuildRequired retry or sets forceFull as a fallback.

Resource verification must accommodate the intended binding edit. Use a dedicated staged adapter operation that verifies the previous variables/styles/libraries and unchanged scene signatures while excluding only checked scene signatures from comparison with their old values. Verify those checked fields against their newly captured values before publication. Leave ordinary matchesVariableEnvironment callers fully guarded.

Resolve newly referenced variables, their collections and aliases, and applied text styles. Enroll their frozen evidence before accepting the candidate; put variables in graph.variables using the existing key/deduplication policy and styles in the style-evidence reader and node snapshots. Update resourceFingerprint and retain dependencies from untouched nodes. If enrollment fails, an existing resource changes, or candidate/inference changes extend beyond the proven closure, require regeneration. Creating a new token is allowed to require regeneration when it changes the global resource inventory.

Add a small commitMicroCheck operation to KnowledgeSessionState. It accepts only the captured document revision and node IDs whose journaled properties were all verified, removes only their journal entries, preserves unverified entries and marks clean only when the journal is empty with no full-build reason. Report publication requires that the complete captured journal was covered. Any intervening edit, including an unrelated remote edit during capture or saving, rejects publication and leaves the previous report and all pending journal entries intact. Do not use completeBuild to clear unverified changes or publish a target-current report over residual dirt.

Use a session-only wholeContextValidatedAt timestamp for successful whole-context validation at an explicit audit/context boundary. Set it after accepting a complete build or after verifying an unchanged graph's clean revision, topology, profile and full resource/scene environment. The latter validation must be reachable even when the old validation timestamp has expired; it permits an aged but unchanged graph to support a new audit without recapture. Keep graph.builtAt as the original capture time. Never restore session validation authority from saved timestamps, and never renew it on a failed or cancelled validation.

Use wholeContextValidatedAt for the existing 15-minute age gate in context status, audit publication, batch continuation, micro-check eligibility, cleanup, waiver management and other guarded actions. Remove graph.builtAt as the competing session-authority clock. For a batch, validate at its start; per-page guards do not renew the timestamp. Micro-checks do not renew it either: expiry before acceptance returns requires-regeneration without an automatic capture or replacement score. An explicit audit can revalidate unchanged context and publish a matching report, after which cleanup uses the renewed timestamp. Expose validation time separately from capture time in context status. All nonhistorical report matching, clean-revision, resource and mutation guards remain in force.

Supported individual plugin fixes feed their known operations into this same verification path after mutation. Replace their unconditional full rescan with bounded verification or the explicit regeneration outcome. A failed check does not claim that already-applied edits were undone. Preserve existing mutation authorization, checkpoints, rollback and Undo behavior.
