**Conductor–Figma design workflow**

Build this flow for both crawl-derived components and manually created components with uploaded screenshots:

**Conductor component → original screenshot reference + editable native wireframe + blank design frame → designer’s replacement → submission linked to the same component.**

Use one manually created or duplicated Figma file per deliverable, containing grouped component workspaces. Extend Design Passport with a connected Conductor area while retaining standalone audits. Native comment synchronization, automatic file provisioning and companion migration remain follow-ups. Generation and submission confer neither design approval nor current readiness.

- [ ] **Implement browser pairing with a scoped COS token.** Add `figma:workspaces` in COS `apps/shell/src/lib/personal-access-tokens/personal-access-token.ts` as a separate pairing-issued scope recognized by plugin authentication and profile token listing/revocation. Keep `PERSONAL_TOKEN_SCOPES` and `isPersonalTokenScope` limited to the manually creatable `read:org` and `write:features` scopes. The profile token-creation API must reject `figma:workspaces`, including mixed-scope requests; hiding the option in the UI is insufficient. Only atomic redemption of an approved, unconsumed pairing may issue a token with exactly this scope. The server issuer computes its expiry eight hours from issuance and enforces that maximum independently of the existing 90-day `expiryRefusal` rule for manual PATs. Profile actions cannot create, re-scope or extend these paired tokens; renewal requires a fresh approved pairing. Bind each token to its COS owner and organization, no broader than that owner’s current access, and restrict it to the plugin API rather than granting general Data API access.

  `POST /api/figma-plugin/v1/pairings` returns a ten-minute pairing ID, verification URL, user code and high-entropy polling secret. Store only the polling-secret hash server-side. The plugin opens the configured COS verification page using `figma.openExternal`; that URL contains the user code, never the polling secret or bearer token. After Entra sign-in, the browser shows the requested access and requires an explicit approval through a same-origin, CSRF-protected action. The plugin polls at five-second intervals and atomically redeems the approved pairing once. An expired or lost redemption requires pairing again. Rate-limit creation, approval attempts and polling. Keep the bearer token only in `figma.clientStorage`, expose listing and revocation through the existing profile token controls, and provide plugin disconnect/revocation. Never place credentials in shared plugin data, URLs or logs.

- [ ] **Bound screenshots and model output.** Reuse the checks in COS `projects/authoring-screenshot-inference.ts`: organization/project/component blob scope, matching storage purpose/container, verified byte length and matching image content type. Allow at most eight selected screenshots per request and 5 MiB per source image. Resolve storage references server-side from the selected variant; never fetch an arbitrary stored URL. Bound decoded images to 24 million pixels. The plugin screenshot endpoint returns validated PNG/JPEG bytes, normalizing other supported upload formats server-side when necessary, with a 5 MiB response cap, a 30-second timeout and no redirects. Preserve the original stored image.

  Register a dedicated governed skill/surface for screenshot wireframes. Use a strict versioned schema allowing only containers, text, rectangle/image placeholders and simple controls. Cap expanded output at 300 native nodes, depth eight, 1,000 characters per text node, 20,000 total text characters and 256 KiB of instruction JSON. Require finite geometry, clamp it to the declared frame bounds and reject invalid dimensions or unknown fields/kinds. Support device widths up to 4,096 px and frame heights up to 16,384 px; oversized inputs require an explicit smaller source or target. Use a 120-second generation deadline, at most 16,384 output tokens and one missing-tool-call retry within that deadline. Validate and normalize on COS, then independently validate the envelope, limits and digest in the plugin before any canvas write. Instructions cannot contain scripts, arbitrary property setters, network URLs or invented library/Code Connect mappings.

- [ ] **Make generation failures useful without inventing a wireframe.** Preserve visible hierarchy and content, label uncertain interpretations, and generate no unseen states or responsive designs. An unavailable, invalid or out-of-scope screenshot fails the item before canvas preparation. If the screenshot is valid but model output is empty, invalid or unavailable, record a retryable generation failure and supply a deterministic fallback containing only the original reference and blank design frame. Track generation outcome separately while that fallback awaits canvas application. Its receipt records the prepared nodes and leaves the item visibly failed for wireframe generation, rather than reporting a successful wireframe. An explicit generation retry creates a new revision item and reuses the existing reference/design workspace where applicable.

- [ ] **Specify claiming, cancellation and recovery.** Normal states are queued → generating → ready_for_canvas → claimed → applied, with failed and cancelled outcomes. A model-failure fallback remains claimable, then finishes failed with its fallback receipt. Derive batch progress from item outcomes and display ready items as waiting for the linked file/plugin. Atomically claim one item with a 120-second lease, heartbeat every 30 seconds and increment a fencing epoch on each claim. Only the current unexpired epoch may heartbeat or finish. Expired claims become reclaimable when the connection and feature remain valid. Reject stale or conflicting receipts; identical completed receipts are no-ops.

Cancellation stops generation and future writes, preserves existing canvas content and records partial progress. Canvas retries reuse the same instructions and stamped nodes; generation retries create new revisions. Do not promise rollback of Figma edits from a COS transaction.
