# Designer-feedback hardening and stale-build prevention

Tracking: [JFusco/design-passport#27](https://github.com/JFusco/design-passport/issues/27)

## Objective

Resolve the false positives and unclear checks reported in four designer walkthroughs, make team conventions configurable without weakening locked safety rules, and make production, development, stale, and historical output visibly distinguishable without adding network access.

## Delivered plan

1. Release plugin `0.4.0` with ruleset `1.0.0-beta.4` and preserve beta.3 rendered-stroke, zero-default, hidden-value, and individual-corner protections.
2. Replace aggregate token coverage with bound, inherited, ignored, and missing evidence; persist exact counts and bounded samples while paging all current live matches.
3. Ignore unsupported typography units, accept semantic category paths, normalize documentation-wrapper scopes, and clarify approved-token-source remediation.
4. Add profile-v2 Required, Advisory, and Off convention modes while keeping safety rules locked.
5. Make detached designs, descriptions, novel terms, and valid spacers non-scoring by default, including a typed per-node detachment acknowledgement.
6. Add report-v3, certificate-v2, producer identity, migrations, historical readers, and separate production/development Figma identities.
7. Verify unit/integration contracts, native Figma behavior, release identity, organization publishing, and rollback procedures; preserve historical artifacts without rewriting them.

## Acceptance evidence

Automated and native evidence, final commit, pull request, organization publication, and rollout communication are recorded in the repository QA record and context wiki created with this delivery.
